# 컴팩트 퀘스트 자동화 편집기 설계

작성일: 2026-07-17

## 1. 목표

퀘스트 수가 많아도 빠르게 훑고 선택할 수 있도록 퀘스트 자동화 목록의 기본 카드 높이를 줄인다. 각 카드는 원본 퀘스트 페이지에서 읽은 미션과 보상 정보를 요약해 보여주며, 실제 전투 설정은 `몬스터 처치`와 `맵 클리어` 미션을 선택했을 때만 같은 카드 안에서 펼친다.

이번 변경은 다음 사용자 경험을 완성한다.

- 기본 카드는 제목, 미션, 보상의 3줄 구조를 사용한다.
- 대화문과 퀘스트 제공자 설명은 표시하지 않는다.
- 전투가 필요 없는 퀘스트는 선택해도 카드 높이가 늘어나지 않는다.
- 전투 미션은 선택한 카드 안에서 맵과 프리셋을 설정한다.
- `전투맵 추가`는 검색과 분류 필터를 제공하는 바텀시트로 연다.
- 선택을 잠시 해제해도 저장 전까지 작성 중인 전투 설정을 복원할 수 있다.

## 2. 범위

### 포함

- HOF 퀘스트 페이지의 보상 텍스트 파싱과 API 응답 추가
- 앱 퀘스트 카드의 컴팩트 요약 레이아웃
- 전투 미션의 인라인 확장 편집기
- 전투맵 검색·필터·추가 바텀시트
- 대표 프리셋 기본값과 맵별 명시적 프리셋 변경
- 선택 해제 취소와 편집 세션 내 설정 복원
- 파서, 도메인 로직, UI 상호작용 테스트

### 제외

- 퀘스트 대화문 또는 퀘스트 제공자 정보 표시
- 전투맵별 실행 횟수 직접 입력
- 퀘스트 실행 우선순위와 오케스트레이터 정책 변경
- 퀘스트·모험맵·전투맵 사이의 실행 스케줄 변경
- 새로운 전투맵 추천 알고리즘

기존 정책대로 몬스터 처치 미션의 여러 맵은 실행 가능한 맵 사이에서 전투 횟수가 최대한 고르게 분배된다. 카드의 맵 순서는 동률이나 다음 후보 선택이 필요한 경우의 안정적인 순서로 사용한다.

## 3. 사용자 인터페이스

### 3.1 목록과 탭

기존 `진행 중`, `수락 가능`, `대기 중` 탭과 검색 입력은 유지한다. 퀘스트는 원본 페이지의 `sourceOrder` 순서로 표시하며 검색은 퀘스트명, 미션 유형, 미션 대상을 대상으로 한다.

각 기본 카드는 다음 세 줄만 표시한다.

1. 선택 체크박스, 퀘스트명, 현재 상태
2. `미션` 요약
3. `보상` 요약

미션이나 보상이 여러 개인 경우 첫 항목을 한 줄로 표시하고 남은 항목 수를 `외 N개`로 표시한다. 긴 텍스트는 한 줄 말줄임 처리한다. 보상 정보가 없으면 `보상 · 없음`을 표시한다. 원본 순서 번호, 미션별 큰 구획, `맵 설정이 필요 없는 미션입니다` 문구는 기본 카드에서 제거한다.

### 3.2 선택 동작

체크박스는 퀘스트 자동화 포함 여부를 변경한다.

- 전투 미션이 없는 퀘스트: 선택 상태만 바뀌며 카드는 계속 3줄 높이를 유지한다.
- `MONSTER_KILL` 또는 `MAP_CLEAR` 미션이 있는 퀘스트: 선택하면 요약 아래에 전투 설정 영역을 펼친다.
- 선택 해제: 카드를 즉시 접고 화면 하단에 `선택 해제됨`과 `되돌리기`를 표시한다.
- 같은 편집 세션에서 되돌리거나 다시 선택: 해제 직전의 맵 순서와 프리셋 설정을 복원한다.
- 해제 상태로 저장: 해당 퀘스트를 저장 요청에서 제외하고 임시 복원 데이터도 버린다.
- 화면을 저장하지 않고 나감: 기존 저장값을 유지하고 편집 세션의 임시 복원 데이터는 버린다.

임시 복원 데이터는 화면 로컬 상태이며 백엔드 계약에 추가하지 않는다. 새로 동기화한 퀘스트에서 미션 키가 사라졌다면 해당 미션의 임시 설정만 복원하지 않는다.

### 3.3 인라인 전투 설정

전투 미션별로 다음 정보를 표시한다.

- 미션 유형과 대상
- 진행도
- 설정 상태: `자동 매칭됨`, `사용자 변경`, `맵 설정 필요`, `프리셋 설정 필요`
- 선택한 전투맵 목록
- 각 맵의 프리셋 선택

`MONSTER_KILL`은 여러 맵을 등록할 수 있다. 맵 행에는 맵 이름, 분류, 적용 프리셋과 제거 동작을 표시한다. 맵 순서 변경은 기존 순서 변경 동작을 유지하되 큰 카드 높이를 만들지 않도록 맵 행 안의 작은 조작으로 제공한다.

`MAP_CLEAR`는 기존 자동 매칭 결과를 첫 맵으로 보여준다. 사용자가 다른 맵을 고르면 단일 맵을 교체하고 `사용자 변경` 상태로 전환한다. 자동 매칭이 유일하지 않거나 실패하면 `맵 설정 필요` 상태에서 사용자가 선택한다.

새로 추가한 맵은 항상 현재 대표 프리셋을 따르는 `PRIMARY`로 시작한다. 사용자는 맵별로 저장된 명시적 프리셋을 선택할 수 있다. 이후 대표 프리셋이 바뀌면 `PRIMARY` 맵은 새 대표 프리셋을 따르고, 명시적 프리셋 맵은 바뀌지 않는다.

### 3.4 전투맵 추가 바텀시트

`전투맵 추가`를 누르면 현재 목록 위에 모달 바텀시트를 연다. 바텀시트는 다음 요소를 갖는다.

- 제목과 현재 몬스터 또는 맵 클리어 대상
- 맵 이름과 그룹명을 대상으로 하는 검색 입력
- `전체`, `전투맵`, `모험맵` 분류 필터
- 맵 이름, 그룹명, 분류와 현재 상태를 포함한 검색 결과
- 추가 버튼 또는 이미 선택된 맵의 `추가됨` 비활성 상태

몬스터 처치 미션에서 `추가`를 누르면 해당 맵을 마지막 순서로 넣고 대표 프리셋을 적용한 뒤 바텀시트를 닫는다. 카드에는 새 맵과 변경된 맵 개수가 즉시 반영된다. 같은 미션에 이미 등록된 맵은 중복 추가할 수 없다.

분류 필터는 카테고리 표시 문자열을 추측하지 않고 API의 안정적인 ID를 사용한다. `전투맵`은 `battle_map`, `모험맵`은 `adventure_map`, `전체`는 이 두 카테고리의 합집합이다. 유니온을 비롯한 다른 카테고리는 결과에서 제외한다.

맵 클리어 미션에서는 버튼 문구를 `전투맵 변경`으로 표시한다. 새 맵을 선택하면 기존 단일 맵을 교체하며, 여러 맵을 만들지 않는다.

모험맵도 후보에서 제외하지 않는다. 자동화 실행 시점에는 기존 정책대로 키, 쿨다운, 일일 횟수와 현재 이용 가능 상태를 확인하고 실행 불가능한 후보를 건너뛴다.

### 3.5 접근성과 화면 크기

- 체크박스, 맵 추가, 필터, 결과 선택, 맵 제거에는 의미 있는 접근성 라벨과 역할을 지정한다.
- 누를 수 있는 영역은 최소 44px을 유지한다.
- 바텀시트 결과는 가상화 목록으로 렌더링하고 키보드가 열리면 검색 입력과 결과가 가려지지 않게 한다.
- 저장과 삭제 하단 버튼은 기존 위치를 유지하며 바텀시트가 열린 동안에는 뒤 화면의 조작을 막는다.

## 4. 데이터 계약과 백엔드

### 4.1 퀘스트 보상 모델

`QuestSnapshot`에 다음 필드를 추가한다.

```text
rewards: List<String>
```

구조화되지 않은 원본 보상 표현을 손실 없이 표시하는 것이 목적이므로 이번 범위에서는 아이템 ID, 수량, 화폐를 별도 필드로 정규화하지 않는다. 각 문자열은 사용자에게 보여줄 한 개의 보상 항목이다. 예시는 `Red Potion(99회 사용가능) ×2`이다.

앱의 `QuestSnapshot` 계약에도 `rewards: string[]`를 추가한다. 응답 정규화 단계에서는 구버전 응답이나 파싱 실패에 대비해 배열이 아니면 빈 배열로 처리한다.

### 4.2 파싱 규칙

`QuestPageParser`는 각 퀘스트의 DOM 범위 안에서 다음 영역을 독립적으로 읽는다.

- 제목과 퀘스트 ID
- 미션 블록
- 보상 블록
- 수락 또는 완료 action

보상 파서는 `보상`으로 표시된 셀 또는 줄의 항목을 DOM 순서대로 수집한다. 줄바꿈과 블록 경계를 항목 경계로 사용하고, 공백을 정규화한다. `미션`, 길드 마스터 대화문, 퀘스트 설명은 보상에 포함하지 않는다. 동일한 보상 문구가 원본에 여러 번 나타나면 원본 표현을 보존하기 위해 자동으로 합치지 않는다.

보상 영역을 찾지 못해도 퀘스트 전체 파싱은 성공하며 빈 목록을 반환한다. 보상 정보는 표시 전용이고 자동화 실행 판단에는 사용하지 않는다.

### 4.3 기존 저장 계약

퀘스트 선택과 맵 설정 저장 요청은 기존 `UpdateQuestAutomationRequest`와 `QuestMapSettingRequest`를 유지한다. 보상은 설정 저장 요청에 포함하지 않는다. 맵 추가 시 `executionOrder`를 다시 0부터 정규화하고, 기본 프리셋은 다음과 같이 보낸다.

```text
presetMode: PRIMARY
partyPresetId: null
```

## 5. 앱 구성 요소와 상태

`QuestAutomationEditor`는 데이터 로딩과 저장 초안을 계속 소유하되, 표시와 상호작용을 다음 단위로 분리한다.

- `QuestSummaryCard`: 3줄 요약, 선택 상태, 인라인 편집기 표시 여부
- `QuestMissionSummary`: 미션 한 줄 요약과 남은 개수 표시
- `QuestRewardSummary`: 보상 한 줄 요약과 빈 상태 표시
- `CombatMissionEditor`: 선택한 전투 미션과 맵 행 편집
- `BattleMapPickerSheet`: 검색, 분류 필터, 중복 방지, 맵 선택

순수 도메인 함수는 다음 책임을 가진다.

- 미션·보상 요약 문자열 생성
- 선택 해제 시 임시 설정 저장과 미션 키 기반 복원
- 맵 분류 필터와 검색
- 몬스터 처치 맵 추가 및 중복 방지
- 맵 클리어 단일 맵 교체
- 맵 순서 정규화와 저장 검증

바텀시트는 현재 편집 중인 `questId`와 `missionKey`만 상태로 들고 실제 맵 배열은 부모 초안이 소유한다. 시트가 닫혀도 이미 반영한 맵은 초안에 남는다.

## 6. 오류 처리

- 퀘스트 목록 로딩 실패: 기존 목록 오류와 재시도 동작을 유지한다.
- 보상 파싱 실패: 퀘스트는 표시하고 `보상 · 없음`으로 대체한다.
- 맵 카탈로그 로딩 실패: 인라인 설정과 바텀시트에 오류와 재시도 버튼을 표시하며 빈 맵을 저장하지 않는다.
- 검색 결과 없음: `검색 결과가 없습니다`를 표시한다.
- 중복 맵: 결과 행을 `추가됨`으로 비활성화하고 도메인 검증에서도 중복 저장을 거부한다.
- 맵 또는 프리셋 누락: 기존 저장 검증을 유지하고 해당 미션에 문제 상태를 표시한다.
- 저장 실패: 편집 초안과 임시 복원 데이터를 유지해 사용자가 다시 저장할 수 있게 한다.

## 7. 테스트

### 백엔드

- 보상 하나와 여러 개를 원본 순서대로 파싱한다.
- 미션과 보상은 서로 섞이지 않는다.
- 대화문과 퀘스트 설명은 보상에 포함되지 않는다.
- 보상 없는 퀘스트는 빈 목록을 반환한다.
- 진행 중, 수락 가능, 대기 중 중복 퀘스트 선택 정책과 `sourceOrder`는 유지된다.
- 컨트롤러 JSON에 `rewards`가 포함된다.

### 앱 도메인

- 긴 미션과 여러 미션을 한 줄 요약으로 만든다.
- 긴 보상과 여러 보상을 한 줄 요약으로 만든다.
- 보상 빈 목록을 `보상 · 없음`으로 만든다.
- 비전투 미션은 맵 편집 대상이 아니다.
- 선택 해제 후 같은 미션 키의 맵과 프리셋을 복원한다.
- 사라진 미션 키의 임시 설정은 복원하지 않는다.
- 몬스터 처치에는 여러 고유 맵을 추가할 수 있다.
- 맵 클리어 선택은 기존 단일 맵을 교체한다.
- 새 맵은 대표 프리셋으로 시작한다.

### 앱 상호작용

- 비선택 카드가 3줄 요약만 표시한다.
- 비전투 퀘스트 선택은 카드를 펼치지 않는다.
- 전투 퀘스트 선택은 같은 카드 안에서 설정을 펼친다.
- 선택 해제, 되돌리기, 재선택 복원이 동작한다.
- 바텀시트 검색과 세 분류 필터가 결과를 갱신한다.
- 이미 선택한 맵은 추가할 수 없다.
- 맵을 추가하면 시트가 닫히고 카드 맵 목록이 갱신된다.
- 맵 클리어 변경은 맵을 하나만 유지한다.
- 화면 읽기 도구가 선택 상태와 각 조작을 구분할 수 있다.

## 8. 완료 조건

- 많은 퀘스트를 스크롤할 때 비선택 카드가 제목·미션·보상 3줄로 유지된다.
- 대화문 없이 원본 퀘스트의 미션과 보상 정보를 확인할 수 있다.
- 전투 미션을 선택한 경우에만 맵 설정이 펼쳐진다.
- 전투맵 추가 바텀시트에서 검색, 분류 필터, 중복 방지와 맵 추가가 동작한다.
- 몬스터 처치에는 여러 맵, 맵 클리어에는 한 맵만 저장된다.
- 새 맵은 대표 프리셋을 따르고 사용자가 맵별 프리셋으로 바꿀 수 있다.
- 선택 해제 후 저장 전에는 전투 설정을 복원할 수 있다.
- 기존 퀘스트 실행 우선순위와 자동화 스케줄은 변경되지 않는다.
