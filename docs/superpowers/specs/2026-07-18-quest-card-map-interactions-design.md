# 퀘스트 카드 선택·맵 편집 인터랙션 설계

작성일: 2026-07-18

## 1. 목표

퀘스트 자동화 목록에서 많은 퀘스트를 빠르게 선택하고, 전투 미션의 맵과 프리셋을 좁은 화면에서도 간결하게 편집할 수 있게 한다. 큰 체크박스, 인라인 프리셋 목록, 순번과 위·아래 버튼, 항상 노출된 삭제 버튼을 제거하고 카드 선택, 검색형 프리셋 선택, 드래그 정렬, 스와이프 삭제로 대체한다.

이번 변경은 표시와 편집 인터랙션만 다룬다. 퀘스트 실행 순서, 몬스터 처치 맵의 자동 균등 분배, 서버 저장 계약은 변경하지 않는다.

## 2. 범위

### 포함

- 체크 표시 없이 카드 요약 영역으로 퀘스트 선택 및 해제
- 선택된 퀘스트를 현재 상태 탭의 상단으로 이동
- 맵별 프리셋을 검색 가능한 바텀시트에서 선택
- 맵 순번과 위·아래 버튼을 왼쪽 드래그 핸들로 교체
- 맵 행의 항상 보이는 삭제 아이콘을 왼쪽 스와이프 후 나타나는 오른쪽 삭제 액션으로 교체
- 기존 균등 분배 안내 문구 제거
- 선택, 정렬, 프리셋, 드래그, 스와이프와 접근성 테스트

### 제외

- 퀘스트 실행 우선순위 변경
- 몬스터 처치 전투 횟수 균등 분배 로직 변경
- 전투맵 또는 모험맵 실행 가능 여부 판단 변경
- 퀘스트, 맵 또는 프리셋 API 변경
- 전체 스와이프만으로 즉시 삭제하는 동작
- 퀘스트 카드 자체의 드래그 정렬

## 3. 퀘스트 카드 선택

### 3.1 카드 구조

퀘스트 카드는 기존의 퀘스트명, 상태, 미션 요약, 보상 요약을 유지한다. 왼쪽의 44px 체크박스와 체크 기호는 제거한다. 제목·미션·보상을 포함하는 요약 영역 전체를 선택 컨트롤로 사용한다.

선택 여부는 다음 시각 상태로만 표현한다.

- 선택되지 않음: 기본 테두리와 기본 배경
- 선택됨: 강조색 테두리와 약한 강조 배경
- 눌림: 짧은 투명도 변화
- 비활성화: 기존 비활성 스타일

요약 영역은 접근성 트리에서 체크박스 역할과 `checked` 상태를 유지한다. 시각적 체크 아이콘을 없애더라도 화면 읽기 도구는 선택 상태를 알 수 있다. 전투 미션 편집기 안의 프리셋, 맵 추가, 드래그, 삭제 조작은 요약 영역 밖에 두어 해당 조작이 퀘스트 선택을 토글하지 않게 한다.

전투가 필요 없는 퀘스트는 선택되어도 카드 높이를 늘리지 않는다. `MONSTER_KILL` 또는 `MAP_CLEAR` 미션이 있는 선택된 퀘스트만 요약 아래에 전투 설정을 펼친다.

### 3.2 선택된 퀘스트 우선 표시

각 `진행 중`, `수락 가능`, `대기 중` 탭 안에서 다음 순서로 표시한다.

1. 선택된 퀘스트
2. 선택되지 않은 퀘스트

각 그룹 내부에서는 HOF 원본 페이지의 `sourceOrder`를 유지한다. 선택을 해제하면 해당 퀘스트는 선택되지 않은 그룹의 원래 `sourceOrder` 위치로 돌아간다. 검색어가 있으면 먼저 현재 탭과 검색 조건을 적용하고, 남은 결과 안에서 같은 규칙으로 선택 항목을 상단에 배치한다.

정렬은 화면 표시만 변경한다. 저장 요청의 퀘스트 배열 순서와 서버 실행 정책은 변경하지 않는다.

## 4. 프리셋 선택

각 맵 행에는 현재 적용 프리셋을 보여주는 단일 버튼만 표시한다. 여러 프리셋을 라디오 칩으로 펼치지 않는다.

버튼 문구는 기존 `formatAutomationPresetSelection` 결과를 사용한다.

- 대표 프리셋 사용: `대표 · {현재 대표 프리셋명}` 또는 `대표 프리셋 없음`
- 명시적 프리셋 사용: 저장된 프리셋명

버튼을 누르면 기존 `BattleMapPresetPickerModal`을 재사용한 바텀시트를 연다. 바텀시트는 다음 동작을 제공한다.

- 맵 이름을 포함한 제목
- `프리셋 이름 검색` 입력
- 현재 선택 상태 표시
- 대표 프리셋 항목을 첫 항목에 고정
- 검색어에 맞는 명시적 프리셋만 표시
- 결과 없음 표시
- 선택 후 바텀시트를 닫고 해당 맵의 초안을 즉시 갱신

`PRIMARY`를 선택한 맵은 이후 대표 프리셋이 변경되어도 새 대표 프리셋을 계속 따른다. 명시적 프리셋은 기존 저장 ID를 유지한다. 모달을 닫으면 검색어를 초기화하고 가능하면 호출한 프리셋 버튼으로 접근성 포커스를 복원한다.

## 5. 맵 순서 변경

맵 행 왼쪽에 작은 `GripVertical` 드래그 핸들을 배치한다. 순번 숫자와 시각적인 위·아래 버튼은 제거한다. 사용자는 핸들을 길게 누른 뒤 세로로 드래그해 같은 미션 안의 맵 순서를 바꾼다.

맵 목록의 각 항목 키는 배열 인덱스가 아니라 `missionKey`, `categoryId`, `mapCode`로 만든 안정적인 식별자를 사용한다. 드래그가 끝나면 새 배열 순서를 0부터 연속된 `executionOrder`로 정규화한 뒤 기존 `onUpdate`로 부모 초안에 반영한다.

드래그 핸들은 접근성에서 adjustable 역할을 사용한다. 시각적인 이동 버튼은 없지만 `increment`와 `decrement` 접근성 액션으로 아래·위 이동을 제공한다. 첫 항목의 위 이동과 마지막 항목의 아래 이동은 노출하지 않는다.

맵 목록은 한 미션 내부의 작은 비스크롤 목록이다. 화면 전체 퀘스트 `FlatList`의 가상화를 유지하고, 드래그 목록 자체의 스크롤은 비활성화해 부모 목록과 세로 스크롤을 경쟁하지 않게 한다.

## 6. 스와이프 삭제

각 맵 행을 `ReanimatedSwipeable`로 감싼다. 기본 상태에서는 삭제 아이콘이나 버튼을 보여주지 않는다. 맵 행을 왼쪽으로 스와이프하면 오른쪽에 고정 폭의 빨간 `삭제` 액션이 나타난다.

- 전체 스와이프만으로 자동 삭제하지 않는다.
- `삭제`를 눌렀을 때만 해당 맵을 편집 초안에서 제거한다.
- 실제 서버 반영은 화면 하단 `저장`을 눌렀을 때 이루어진다.
- 삭제 후 저장하지 않고 화면을 나가면 기존 서버 설정은 유지된다.
- 한 미션에서 한 행만 열린 상태를 유지한다.
- 다른 행을 열거나 드래그를 시작하거나 맵 배열이 바뀌면 기존 열린 행을 닫는다.
- 편집이 비활성화된 동안에는 스와이프와 삭제를 비활성화한다.

삭제 액션은 `${퀘스트명} · ${미션명} · ${맵명} 삭제` 접근성 버튼으로 노출한다. 스와이프가 어려운 보조기기에서는 맵 행의 접근성 `delete` 액션으로 같은 삭제 동작을 실행할 수 있게 한다.

드래그는 왼쪽 핸들에서만 시작하고 스와이프는 맵 행 본문에서 시작한다. 프리셋 버튼을 누르는 동작은 두 제스처를 시작하지 않는다.

## 7. 균등 분배 안내

`여러 맵을 실행 가능한 순서대로 확인하고 전투 횟수를 고르게 분배해요` 문구는 화면에서 제거한다. 몬스터 처치 퀘스트의 성공 전투 균등 분배 로직은 기존대로 자동 동작한다. 편집 화면에서는 실행 시점에 정해지는 분배 결과를 미리 설명하거나 숫자로 표시하지 않는다.

## 8. 컴포넌트와 도메인 경계

### `QuestAutomationEditor`

- 현재 탭, 검색, 초안과 선택 상태를 소유한다.
- 선택된 퀘스트 ID 집합을 표시 정렬 함수에 전달한다.
- 저장 초안의 퀘스트 순서는 기존 정책을 유지한다.

### `QuestSummaryCard`

- 요약 영역 선택과 선택 시각 상태를 담당한다.
- 시각적 체크박스는 렌더링하지 않는다.
- 선택된 전투 미션에만 `CombatMissionEditor`를 렌더링한다.

### `CombatMissionEditor`

- 미션의 맵 목록, 프리셋 모달 대상, 열린 스와이프 행을 관리한다.
- 드래그 종료, 스와이프 삭제와 프리셋 변경을 기존 `onUpdate` 계약으로 전달한다.
- 기존 `BattleMapPickerSheet`와 `BattleMapPresetPickerModal`을 재사용한다.

### 순수 도메인 함수

- `filterQuests`는 탭과 검색 및 원본 순서 필터링 책임을 유지한다.
- 별도의 선택 우선 정렬 함수는 선택 ID 집합을 받아 선택/비선택 그룹을 안정적으로 분리한다.
- 맵 재정렬 함수는 새 배열 순서를 `executionOrder`와 함께 정규화한다.

UI 제스처 상태와 열린 모달 상태는 저장 계약에 포함하지 않는다.

## 9. 오류 및 경계 상황

- 프리셋 목록 로딩 중 또는 실패: 기존 상위 로딩·오류·재시도 표시와 저장 차단 정책을 유지한다. 모달은 대표 프리셋 항목을 계속 제공하고, 아직 불러오지 못한 명시적 프리셋은 결과에 표시하지 않는다.
- 대표 프리셋 없음: `대표 프리셋 없음`을 표시하되 `PRIMARY` 선택 자체는 유지한다.
- 검색 결과 없음: 바텀시트에 `검색 결과가 없습니다`를 표시한다.
- 맵 하나만 있음: 드래그 핸들은 표시하되 이동 접근성 액션은 제공하지 않는다.
- 맵 삭제로 미션의 맵이 0개가 됨: 기존 `맵 설정 필요` 검증을 표시하고 저장을 차단한다.
- 드래그 중 목록 갱신 또는 비활성화: 드래그를 종료하고 서버에서 새로 저장하지 않으며 현재 초안 상태를 기준으로 다시 렌더링한다.
- 삭제된 프리셋 ID: 기존 검증과 `프리셋 설정 필요` 표시를 유지한다.

## 10. 테스트

### 도메인

- 선택된 퀘스트를 탭 상단으로 올린다.
- 선택된 퀘스트끼리와 비선택 퀘스트끼리는 각각 `sourceOrder`를 유지한다.
- 선택 해제하면 원래 `sourceOrder` 위치로 돌아간다.
- 검색 결과 안에서도 선택 우선 정렬이 동일하게 적용된다.
- 맵 드래그 결과를 새 순서와 연속된 `executionOrder`로 정규화한다.

### 퀘스트 카드

- 큰 체크박스와 체크 기호를 렌더링하지 않는다.
- 요약 영역을 누르면 선택 콜백을 한 번 호출한다.
- 접근성 체크 상태와 비활성 상태를 전달한다.
- 선택 상태는 카드 테두리와 배경으로 표시한다.
- 내부 편집기 조작은 퀘스트 선택을 토글하지 않는다.

### 전투 미션 편집기

- 인라인 라디오 칩 대신 현재 프리셋 버튼 하나를 표시한다.
- 프리셋 버튼이 검색 모달을 열고, 검색과 선택이 해당 맵만 갱신한다.
- 대표 프리셋과 명시적 프리셋 선택을 구분한다.
- 드래그 종료가 맵 순서를 갱신한다.
- 시각적인 순번과 위·아래 버튼이 렌더링되지 않는다.
- 왼쪽 스와이프가 오른쪽 삭제 액션을 노출한다.
- 삭제 액션이 올바른 맵만 초안에서 제거한다.
- 한 번에 하나의 스와이프 행만 열린다.
- 드래그, 스와이프, 프리셋 버튼 입력이 서로의 콜백을 실행하지 않는다.
- 균등 분배 안내 문구가 렌더링되지 않는다.

### 전체 검증

- 앱 전체 테스트를 실행한다.
- TypeScript 타입 검사를 실행한다.
- Android 개발 빌드에서 카드 선택, 검색, 드래그와 스와이프를 수동 확인한다.

## 11. 완료 조건

- 퀘스트 카드에 큰 체크박스나 체크 기호가 없고 카드 자체가 선택 상태로 보인다.
- 각 상태 탭의 선택된 퀘스트가 원본 상대 순서를 유지한 채 상단에 표시된다.
- 선택 해제한 퀘스트가 원본 HOF 페이지 순서로 돌아간다.
- 맵별 프리셋을 검색 가능한 바텀시트에서 선택할 수 있다.
- 맵 순번과 위·아래 버튼 없이 왼쪽 핸들 드래그로 순서를 변경할 수 있다.
- 항상 보이는 삭제 아이콘 없이 왼쪽 스와이프로 오른쪽 삭제 액션을 열 수 있다.
- 균등 분배 안내 문구만 사라지고 자동 균등 분배 로직은 유지된다.
- 기존 저장 API와 백엔드 코드는 변경되지 않는다.
