# 인증 상태·퀘스트 블록 파싱·전체 요약 표시 설계

작성일: 2026-07-18

## 1. 목표

HOF 로그인 세션이 만료되었을 때 공개 페이지의 다른 사용자명을 상단 상태바에 표시하지 않는다. 실제 퀘스트 페이지의 연속 행 구조를 퀘스트 단위로 묶어 미션을 정확히 파싱하고, 앱의 퀘스트 카드에서 모든 미션과 보상을 숨김없이 확인할 수 있게 한다.

이번 설계는 기존 `컴팩트 퀘스트 자동화 편집기`의 카드와 맵 설정 동작을 유지하면서 다음 잘못된 동작을 바로잡는다.

- `Time -`, `Fund $-` 상태에서 공개 페이지의 `《타이틀》사용자명`이 표시되는 문제
- 퀘스트 기본 행 다음의 별도 미션 행을 놓쳐 `미션 · 없음`으로 표시되는 문제
- 복수 미션과 보상을 첫 항목 및 `외 N개`로 축약하는 문제

## 2. 범위

### 포함

- `/api/status`의 HOF 로그인 상태 검증
- 상태 헤더 DOM 범위에 한정한 플레이어 표시명 파싱
- 연속된 퀘스트 테이블 행의 블록 파싱
- 복수 미션과 진행도 전체 표시
- 복수 보상 전체 표시
- 백엔드 파서·서비스와 앱 도메인·컴포넌트 회귀 테스트

### 제외

- HOF 계정 ID와 플레이어 표시명의 동일성 검증
- 퀘스트 대화문 또는 제공자 설명 표시
- 미션·보상 데이터의 아이템 ID나 화폐 단위 정규화
- 퀘스트 실행 우선순위, 자동화 실행기, 맵 추천 정책 변경
- 퀘스트 검색 대상 변경

## 3. 상태 조회 설계

### 3.1 데이터 흐름

`HofStatusService`는 저장된 쿠키로 HOF 홈을 호출한 다음, 상태 값을 파싱하기 전에 `LoginStateParser`로 응답 HTML을 검사한다.

1. 백엔드 계정이 없으면 기존 `RESOURCE_NOT_FOUND`를 반환한다.
2. 저장된 HOF 쿠키가 없으면 기존 `HOF_SESSION_EXPIRED`를 반환한다.
3. HOF 홈 응답이 로그인 상태로 판정되지 않으면 `HOF_SESSION_EXPIRED`를 반환한다.
4. 로그인 상태가 확인된 응답만 `HofMainStatusParser`로 전달한다.

쿠키가 존재한다는 사실만으로 HOF 로그인이 유효하다고 간주하지 않는다. 앱은 기존 인증 오류 처리 경로를 사용해 사용자가 HOF 재로그인 절차를 밟도록 한다.

### 3.2 플레이어 표시명 경계

`HofMainStatusParser`는 문서 전체에서 처음 발견되는 `《타이틀》이름`을 사용하지 않는다. `Funds`와 `Time`이 포함된 인증 상태 헤더의 소유 행 또는 가장 가까운 상태 컨테이너를 먼저 찾고, 그 DOM 범위 안의 표시명만 사용한다.

상태 컨테이너 안에서 이름을 찾지 못하면 `Unknown`을 반환한다. 공개 랭킹, 현재 접속자, 캐릭터 목록 등 상태 헤더 밖의 이름은 fallback으로 사용하지 않는다.

## 4. 퀘스트 블록 파싱 설계

### 4.1 블록 경계

실제 HOF 퀘스트 테이블은 한 퀘스트를 여러 형제 `tr`로 표현할 수 있다. 퀘스트 ID와 이름이 있는 시작 행 뒤에 미션과 설명 행이 이어지고, 다음 퀘스트 시작 행에서 현재 퀘스트가 끝난다.

파서는 같은 소유 테이블 안에서 다음 규칙으로 블록을 만든다.

1. 직접 셀에 퀘스트 ID가 있거나 `data-quest-id`가 있는 노드를 시작점으로 삼는다.
2. 시작 행 다음의 형제 행을 DOM 순서대로 수집한다.
3. 다음 퀘스트 시작 행, 테이블 끝 또는 섹션 경계에서 블록을 끝낸다.
4. 중첩 테이블의 행은 현재 블록에 포함하지 않는다.
5. `data-quest-id` 독립 컨테이너는 기존처럼 자체 블록으로 처리한다.

`sourceOrder`, 중복 퀘스트 우선순위, 섹션 판정은 시작 행을 기준으로 기존 정책을 유지한다.

### 4.2 필드별 소유 범위

- 퀘스트 ID와 이름: 시작 행에서만 읽는다.
- 미션: 블록 전체에서 `미션 :` 또는 `미션：`로 시작하는 표시 줄만 DOM 순서대로 읽는다.
- 보상: 시작 행의 보상 열과 블록 안의 명시적인 `보상:` 영역만 읽는다.
- 수락·완료 action과 `no`: 블록 전체에서 읽어 별도 후속 행 형태도 지원한다.
- 대화문·설명: 저장하거나 앱에 전달하지 않는다.

문장 중간에 `미션`이라는 단어가 있다는 이유만으로 미션으로 분류하지 않는다. 보상의 `미션 포인트`와 대화문의 일반 문장은 미션 목록에 들어가지 않는다.

### 4.3 미션 모델

기존 `QuestMission` 계약을 유지한다. 미션 유형, 대상, 진행도, 완료 가능 여부, semantic key 계산도 유지한다. 복수 미션은 원본 표시 순서를 보존한다.

## 5. 앱 카드 표시 설계

### 5.1 미션

카드는 모든 미션을 원본 순서대로 표시한다. 각 항목은 기존 한국어 미션 라벨과 대상 뒤에 진행도가 있으면 `현재/필요` 값을 붙인다.

예시:

```text
미션 · 몬스터 처치 · Killer Maid 12/30 · 맵 클리어 · 천공성(제 2탑) · 아이템 반납 · Silver Key 1/1
```

미션이 없을 때만 `미션 · 없음`을 표시한다.

### 5.2 보상

카드는 빈 문자열을 제외한 모든 보상을 원본 순서대로 ` · `로 연결한다. `외 N개` 표현은 사용하지 않는다.

예시:

```text
보상 · Red Potion ×2 · Blue Potion ×2 · Fund $15,000
```

보상이 없을 때만 `보상 · 없음`을 표시한다.

### 5.3 레이아웃

미션과 보상은 각각 하나의 논리적 텍스트 행으로 구성하지만 `numberOfLines` 제한을 두지 않는다. 화면 폭을 넘으면 단어 경계에 맞춰 자연스럽게 여러 줄로 감싼다. 항목마다 강제 줄바꿈하지 않아 카드 높이 증가를 최소화한다.

전투 미션 선택 시 인라인 맵 편집기를 펼치는 기존 동작, 체크박스, 탭, 하단 저장·삭제 영역은 변경하지 않는다.

## 6. 오류 처리

- 만료된 HOF 홈: 상태 값을 반환하지 않고 `HOF_SESSION_EXPIRED`로 재로그인을 요구한다.
- 인증 상태지만 상태 헤더 이름 누락: 플레이어명은 `Unknown`으로 반환하고 다른 사용자명을 추측하지 않는다.
- 퀘스트 블록에 미션 없음: 빈 미션 목록을 반환한다.
- 식별 불가능한 보상 영역: 빈 보상 목록을 반환한다.
- 일부 미션 또는 보상 항목이 비어 있음: 빈 항목만 제외하고 나머지 순서는 유지한다.

## 7. 테스트

### 백엔드 상태

- 만료된 로그인 페이지에 다른 `《타이틀》사용자명`이 있어도 상태 응답을 만들지 않는다.
- 유효한 상태 헤더의 플레이어명, Funds, Time, Work, Auction을 기존처럼 반환한다.
- 상태 헤더 밖의 사용자명은 플레이어명 fallback으로 사용하지 않는다.

### 백엔드 퀘스트

- 시작 행과 후속 미션 행을 한 퀘스트로 묶는다.
- 다음 퀘스트 시작 행에서 블록을 정확히 끊는다.
- 한 퀘스트의 복수 미션과 진행도를 원본 순서로 파싱한다.
- 후속 대화문과 `미션 포인트` 보상은 미션으로 파싱하지 않는다.
- 시작 행의 복수 보상을 기존 순서대로 유지한다.
- 중첩 테이블 행과 다음 퀘스트의 미션·보상이 섞이지 않는다.
- 기존 섹션, 상태, action, semantic key 테스트가 계속 통과한다.

### 앱

- 복수 미션을 진행도와 함께 모두 연결한다.
- 복수 보상을 `외 N개` 없이 모두 연결한다.
- 미션·보상 빈 상태 문구를 유지한다.
- 카드 텍스트에 한 줄 제한이 없다.
- 전투 미션만 기존 맵 편집기를 펼친다.

## 8. 완료 조건

- 만료된 HOF 세션에서 공개 페이지의 다른 사용자명이 상단에 표시되지 않는다.
- 실제 연속 행 형태의 퀘스트에서 미션이 `없음`으로 누락되지 않는다.
- 카드에서 모든 미션, 진행도, 보상을 확인할 수 있다.
- `외 N개` 문구가 미션과 보상 카드에 남지 않는다.
- 대화문과 설명은 카드에 표시되지 않는다.
- 기존 퀘스트 선택, 맵 설정, 저장 계약과 자동화 실행 정책은 바뀌지 않는다.
