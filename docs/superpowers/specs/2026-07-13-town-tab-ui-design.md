# 마을 탭 UI 설계

작성일: 2026-07-13

## 1. 목표

기존 Expo 앱의 `마을` placeholder를 APK의 마을 메뉴 구조를 반영한 실제 화면으로 교체한다.

이번 단계에서는 사용자가 마을 기능을 분류별로 탐색하고 메뉴 하나를 선택할 수 있는 화면 틀만 만든다. 구매, 교환, 입찰, 낚시, 제작, 제련 같은 HOF 서비스 호출은 연결하지 않는다. 이후 각 메뉴의 실제 서비스를 추가할 때 상위 화면 구조를 다시 바꾸지 않고 선택된 메뉴의 상세 영역만 확장할 수 있어야 한다.

## 2. 범위

포함한다.

- 기존 상단 `GameStatusBar`와 하단 `BottomTabBar` 사이의 마을 화면
- `마을 / 퀘·교환` 하위 탭
- 뒤로가기 없이 항상 노출되는 마을 카테고리 선택 영역
- 선택한 카테고리에 해당하는 2열 메뉴 목록
- 선택한 메뉴의 강조 상태와 간결한 준비 상태 영역
- APK에서 확인한 마을 메뉴 이름, 내부 식별자, 24px 아이콘 자산
- Android 우선 반응형 레이아웃과 접근성 상태

포함하지 않는다.

- 백엔드 마을 API, parser, DTO 또는 DB 변경
- HOF 페이지 조회와 form 제출
- 구매, 입찰, 교환, 제작, 낚시 또는 제련 실행
- 로딩, 서버 오류, CAPTCHA 처리
- `퀘·교환`의 실제 퀘스트 자동화 화면 연결
- 메뉴 선택을 앱 재시작 이후까지 저장하는 기능

## 3. APK에서 확인한 원본 구조

기준 APK는 `example/mobile_analysis/app.apk`이며 package는 `com.nova.mobile`, version은 `3.56`이다. 디컴파일된 `Nova.js`의 `renderTown()`과 `content.js`의 마을 메뉴 parser를 기준으로 한다.

원본 APK는 14개 마을 기능을 2열 버튼으로 보여주고 선택한 기능의 상세 카드를 아래에 렌더링한다. 현재 Expo 앱에는 상세 서비스를 호출할 API가 없으므로, 이번 단계에서는 같은 기능 목록과 선택 구조만 구현한다.

## 4. 화면 구조

화면은 위에서 아래 순서로 구성한다.

1. 앱 공통 `GameStatusBar`
2. `마을 / 퀘·교환` 하위 탭
3. 선택한 하위 탭의 내용
4. 앱 공통 `BottomTabBar`

`마을` 하위 탭은 다음 순서로 구성한다.

1. 한 줄 안내
2. 항상 보이는 카테고리 탭: `생활`, `상점`, `카드`, `제작`
3. 선택한 카테고리의 2열 메뉴 그리드
4. 선택한 메뉴 이름과 `서비스 준비 중` 상태를 보여주는 상세 영역

`퀘·교환` 하위 탭은 이번 단계에서 간결한 준비 상태만 보여준다. 화면 전환은 동작하지만 실제 퀘스트 UI로 이동하지 않는다.

## 6. 상호작용

### 6.1 기본 상태

- 마을 화면에 처음 들어오면 `마을` 하위 탭과 `생활` 카테고리를 선택한다.
- 생활 메뉴 2개를 즉시 보여준다.
- 아직 메뉴를 누르지 않았다면 상세 영역에는 `메뉴를 선택해 주세요`를 보여준다.

### 6.2 카테고리 전환

- 카테고리는 화면에서 사라지지 않는다.
- 사용자가 다른 카테고리를 누르면 아래 메뉴 그리드만 즉시 교체한다.
- 별도 상세 화면으로 이동하지 않으므로 뒤로가기 버튼을 두지 않는다.
- 카테고리를 변경하면 이전 카테고리에서 선택했던 메뉴 강조를 해제한다.

### 6.3 메뉴 선택

- 메뉴 버튼을 누르면 해당 버튼을 선택 상태로 강조한다.
- 상세 영역의 제목을 선택한 메뉴 이름으로 바꾼다.
- 상세 영역에는 이번 범위를 명확히 하는 `서비스 준비 중` 문구만 표시한다.
- 같은 메뉴를 다시 누르더라도 별도 navigation이나 API 요청은 발생하지 않는다.

### 6.4 하위 탭 전환

- `퀘·교환`을 누르면 마을 카테고리와 메뉴 그리드를 숨기고 준비 상태를 표시한다.
- `마을`로 돌아오면 컴포넌트가 유지되는 동안 마지막 카테고리와 메뉴 선택을 유지한다.

## 7. 시각 설계

- 기존 `theme.ts`의 배경, surface, border, text, accent 색상을 그대로 사용한다.
- 하위 탭과 카테고리의 선택 상태는 기존 앱의 파란색 또는 황금색 accent 체계를 따른다.
- 메뉴는 작은 Android 화면에서도 이름이 잘리지 않도록 2열을 유지하고 각 버튼에 충분한 세로 터치 영역을 둔다.
- APK에서 추출한 24x24 아이콘을 원본 비율로 사용하고 장식 이미지로 처리한다.
- 메뉴 버튼에는 아이콘과 화면 이름만 표시한다. 내부 코드, 상태 배지, 설명 문단은 넣지 않는다.
- 화면 전체는 현재 앱처럼 세로 스크롤할 수 있지만 카테고리 자체를 별도 수평 스크롤로 만들지 않는다.

## 8. 코드 구조

### 8.1 도메인 카탈로그

`src/main/domain/townMenus.ts`에 다음을 둔다.

- `TownSectionId`
- `TownCategoryId`
- `TownMenuId`
- 카테고리 및 메뉴 타입
- APK 메뉴 값과 아이콘을 포함한 읽기 전용 카탈로그
- 카테고리별 메뉴 조회 helper

메뉴 순서와 카테고리 매핑은 화면 컴포넌트에 중복 작성하지 않는다.

### 8.2 화면

`src/main/screens/TownTabScreen.tsx`가 하위 탭, 선택 카테고리, 선택 메뉴의 로컬 상태를 관리한다. 현재 `MainScreen.tsx`의 `PlaceholderTabScreen` 분기를 이 화면으로 교체한다.

컴포넌트를 나눌 필요가 생기면 다음 경계만 사용한다.

- 카테고리 선택 영역
- 메뉴 그리드
- 선택 메뉴 준비 상태

이번 범위에서 범용 navigation framework나 전역 store를 새로 추가하지 않는다.

### 8.3 자산

APK의 `assets/icons/town`에서 실제 사용하는 8개 아이콘을 Expo 앱의 `assets/town`으로 복사하고 정적 `require` 매핑을 사용한다. 네트워크 URL이나 APK 분석 디렉터리를 runtime 경로로 참조하지 않는다.

## 9. 접근성

- 하위 탭과 카테고리 버튼에 선택 상태를 제공한다.
- 메뉴 버튼은 화면 이름을 접근성 이름으로 사용한다.
- 선택은 색상만으로 표현하지 않고 border와 텍스트 상태도 함께 바꾼다.
- 터치 영역은 Android에서 누르기 쉬운 크기를 유지한다.
- 장식용 아이콘은 스크린 리더가 중복 읽지 않게 한다.

## 10. 검증

도메인 테스트는 다음을 검증한다.

- 카테고리 순서가 `생활`, `상점`, `카드`, `제작`이다.
- 14개 메뉴가 빠짐없이 한 카테고리에만 속한다.
- APK 메뉴 값과 화면 이름 매핑이 설계와 일치한다.
- 카테고리별 메뉴 순서가 APK 화면 순서를 보존한다.

화면 테스트는 다음을 검증한다.

- 마을 탭이 placeholder 대신 `TownTabScreen`을 사용한다.
- 기본 카테고리는 생활이다.
- 카테고리 변경 시 메뉴 목록이 교체되고 이전 선택이 해제된다.
- 메뉴를 누르면 선택 상태와 상세 제목이 바뀐다.
- `퀘·교환` 전환과 마을 복귀가 동작한다.
- 메뉴 선택으로 백엔드 요청이 발생하지 않는다.

마지막으로 Android 폭 기준에서 2열 버튼 이름, 카테고리, 하단 탭이 겹치지 않는지 확인한다.

## 11. 이후 확장

실제 서비스 연결 단계에서는 `TownMenuId`별 상세 컴포넌트와 backend callback을 추가한다. 상단 하위 탭, 고정 카테고리, 메뉴 카탈로그는 그대로 유지한다.

서비스 연결 우선순위는 별도 설계에서 정한다. UI 단계에서 임의의 HOF form 요청이나 모의 성공 결과를 만들지 않는다.
