# 자동화 카드 직접 진입·스와이프 삭제 설계

## 목적

자동화 설정 목록의 점 3개 메뉴를 제거하고, 항목을 누르면 바로 상세 설정으로 이동하도록 단계를 줄인다. 삭제는 카드를 왼쪽으로 스와이프했을 때 오른쪽에 나타나는 삭제 버튼으로 제공한다.

## 확정된 인터랙션

- 카드의 아이콘·제목·요약 영역을 누르면 해당 자동화의 상세 설정 화면으로 바로 이동한다.
- 왼쪽 드래그 핸들은 길게 눌러 우선순위를 변경하는 기존 동작을 유지한다.
- 오른쪽 활성화 스위치는 기존처럼 해당 자동화의 활성 상태만 변경한다.
- 카드를 왼쪽으로 스와이프하면 오른쪽에 빨간색 `삭제` 버튼이 나타난다.
- 삭제 버튼을 눌러도 즉시 삭제하지 않고 기존 확인 Alert를 표시한다.
- 오른쪽으로 되밀거나 다른 카드를 열면 노출된 삭제 버튼을 닫는다.
- 전체 스와이프만으로 즉시 삭제하는 동작은 제공하지 않는다.

## 컴포넌트 구조

`UnifiedAutomationSettings`의 각 `AutomationEntryRow`를 `react-native-gesture-handler`의 `ReanimatedSwipeable`로 감싼다. `renderRightActions`는 고정 폭의 삭제 버튼을 렌더링한다.

카드 본문은 `Pressable`로 만들고 `onDetail(item)`을 직접 호출한다. 드래그 핸들과 스위치는 본문 Pressable 바깥의 독립 컨트롤로 유지해 탭, 가로 스와이프, 세로 정렬, 토글 입력이 서로의 콜백을 실행하지 않게 한다. 기존 `MoreHorizontal` 버튼과 상세/삭제 Modal은 제거한다.

한 번에 하나의 행만 열린 상태를 유지한다. 새 행의 스와이프가 열리면 이전 행을 닫고, 상세 진입·삭제 요청·목록 구조 변경 시에도 열린 행을 정리한다.

## 상태와 오류 처리

- `savingEntryIds`에 포함된 행은 상세 진입, 스와이프 삭제, 스위치 변경을 비활성화한다.
- 우선순위 저장 중에는 드래그 동작만 기존과 동일하게 제한하며 상세 진입은 허용한다.
- 삭제 확인 후 `onDelete`가 성공하면 서버 응답으로 목록에서 행이 제거된다.
- 삭제 실패 시 행은 유지하고 기존 상위 오류 표시를 사용한다.
- 삭제 확인창을 열기 전에 스와이프 행을 닫아 Alert가 사라진 뒤 중간 상태가 남지 않게 한다.

## 접근성

- 카드 본문은 `${유형명} 상세 설정` 버튼으로 노출한다.
- 드래그 핸들의 adjustable 역할과 위·아래 이동 접근성 액션은 유지한다.
- 스위치의 켜기·끄기 레이블은 유지한다.
- 삭제 버튼은 `${유형명} 삭제` 버튼으로 노출하며 저장 중 상태를 전달한다.
- 스와이프를 수행하기 어려운 보조기기에서도 삭제 버튼에 접근할 수 있도록 삭제 액션을 접근성 트리에 유지한다.

## 테스트

- 카드 본문 탭이 메뉴 없이 `onDetail`을 한 번 호출하는지 검증한다.
- 왼쪽 스와이프의 오른쪽 액션이 삭제 확인 Alert를 열고, 확인 후 올바른 entry ID를 삭제하는지 검증한다.
- 저장 중인 행에서 상세 진입·삭제·스위치가 비활성화되는지 검증한다.
- 점 3개 버튼과 상세/삭제 Modal이 더 이상 렌더링되지 않는지 검증한다.
- 드래그 정렬과 스위치 토글 기존 테스트를 유지한다.
- 전체 앱 테스트와 TypeScript 타입 검사를 실행한다.

## 범위 제외

- 퀘스트·전투맵·모험맵 상세 편집 화면 자체는 변경하지 않는다.
- 백엔드 API와 삭제 확인 문구는 변경하지 않는다.
- 전체 스와이프 즉시 삭제, 실행 취소 토스트, 다중 선택 삭제는 추가하지 않는다.
